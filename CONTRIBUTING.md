# Contributing

## Development Workflow

1. Fork the repository or create a feature branch.
2. Keep changes focused and explain the reason for the change.
3. Run the available checks before opening a pull request.
4. Update documentation when behavior or setup changes.
5. Open a pull request with a clear summary and testing notes.

## Commit Messages

Use concise, imperative commit messages such as:

- `feat: add workspace search`
- `fix: handle empty channel state`
- `docs: update local setup`

## Pull Requests

Include the problem, the solution, screenshots for UI changes, and the commands used to validate the changes.
